# 回归检查清单

这些检查面向在 NextMail 自身上工作的开发者和 AI 代理，目标是那些容易被悄悄
破坏的部分：Catch-all 身份、未读计数、增量轮询和多域名路由。

在修改 `app/**`、`workers/**`、Drizzle 迁移或部署脚本后执行它们。Node 测试套件
通过**不能**证明生产环境的 Cloudflare 收信、Resend 或 Webhook 投递正常。

## 开始之前

```bash
npm run db:migrate-local
```

迁移 `0020_user_email_domain_access.sql` 保存按用户的域名权限，
`0021_message_read_tracking.sql` 新增已读状态与统计索引，
`0022_stable_mail_delivery.sql` 保存 Catch-all 的稳定映射，并为已有和新的邮件
建立到达序号。

已有邮件默认未读，已有用户默认继承全部已配置域名。到达序号由插入触发器生成，
因此不依赖邮件时间戳或随机 ID。删除邮件会清理对应记录，但绝不复用已提交的
序号。

## 聚焦检查

```sh
node --import tsx --experimental-test-module-mocks --test \
  tests/catch-all-config.test.ts \
  tests/mailbox-controls.test.ts \
  tests/email-receiver.test.ts \
  tests/routes.test.ts \
  tests/message-list-refresh.test.ts \
  tests/mailbox-events.test.ts
```

然后执行完整流程——lint、TypeScript、单元测试和 Worker 构建。

## 浏览器检查

使用两个收件域名检查 `/en/mailbox`、`/zh-CN/mailbox` 以及对应的个人中心页面。
验证 Catch-all 开关、前缀、关闭后仍显示、域名筛选和按域名的 Resend 设置。

把普通用户限制为只有一个域名，用该用户登录，确认创建选项和 API 拒绝行为都
符合预期。

打开一封未读邮件：标题必须恢复常规字重，计数必须恰好减少一次。

### 移动端对话框

运行 `npm run dev`，用可以管理邮箱的账号登录，在 Chromium 中以 390 × 844 的
尺寸打开 `/en/mailbox`。点击**创建邮箱**，确认前缀、可选域名选择器、四个有效期
选项和两个操作按钮都能在对话框内显示，无需水平滚动。使用多个已配置域名重复
验证；控件必须能换行并保持可用。动画结束后截图。

### 邮箱统计竞态

打开只有一封未读邮件的邮箱，再加入第二封未读邮件。先刷新左侧邮箱列表，确认
统计为 `2 / 2`；然后等待邮件轮询周期，统计必须仍为 `2 / 2`。交换刷新与轮询
顺序重复一次，再等待经过一轮空的增量轮询——计数绝不能重复累计。

### 置顶邮箱分页

先只加载 Catch-all 邮箱，在另一会话中新增 21 个普通邮箱，然后刷新并滚动到底。
全部 22 个邮箱必须可见且没有重复；普通邮箱分页重叠时，仍需保留原有的分页末尾。

### 配置错误提示的语言

分别在 `/en/profile` 和 `/zh-CN/profile` 保存无效的 Catch-all 前缀、已占用地址
和空的已启用邮箱名，确认提示使用当前语言。模拟未知服务端错误或请求失败时，
界面应显示当前语言的通用保存失败提示，绝不显示服务端原始文本。

### Catch-all 保存与恢复

在"数据库重命名已成功、KV 尚未保存"的窗口内向未知地址投递邮件，邮件必须进入
原邮箱。模拟首次保存或重命名时的 KV 写入失败，再提交相同配置——必须复用原
邮箱并成功保存，原邮件保留。失败的旧配置仍启用时，收件也必须能通过稳定映射
进入原邮箱。

### Catch-all 并发与发信

让两个首次保存请求使用不同前缀，并在两个请求都读到旧配置后交错完成。最终只能
保留同一个注册邮箱，先完成请求后的收件不能丢失。

重命名后保留旧 KV 地址，分别通过皇帝会话和 API Key 用原前缀与自定义前缀发信，
两者都应成功并保存正确的发件地址。复用旧地址的普通邮箱以及任何非皇帝角色都
不能修改发件前缀。

### 延迟收件

首次快照后插入时间相同但 ID 更小、或时间更早的邮件；增量轮询必须收到它们，
列表仍按邮件时间显示。超过一页时逐页排空，插入新邮件并删除全部旧邮件后继续
检查，不能遗漏或重复显示。

### 跨会话已读

从两封未读邮件开始，在另一会话读取其中一封。等待当前页面轮询显示 `1 / 2`，
再打开本页仍加粗的同一行，计数必须保持 `1 / 2`；只有打开另一封才变为 `0 / 2`。
分别检查英文、中文、桌面端和移动端视口。

## 这些检查无法证明什么

单元测试和本地模拟不能证明生产环境的 Cloudflare 能收信、Resend 能投递或
Webhook 投递正常。这些需要在已部署的环境中验证——见
[部署与运维](/developers/deployment)。
