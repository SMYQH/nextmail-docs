# AGENTS.md

## Repository Scope

This repository hosts the NextMail documentation site. Application code lives in [SMYQH/nextmail](https://github.com/SMYQH/nextmail).

## Technology Stack

- Docusaurus 3.10.2 (`@docusaurus/core` + `@docusaurus/preset-classic`)
- React 19 + TypeScript
- Fluent 2: `@fluentui/react-theme` design tokens, and `@fluentui/react-icons` icons
- `@easyops-cn/docusaurus-search-local` local search

## I18n

- English is the default locale and is served at `/en/`; Simplified Chinese is served at `/zh-CN/`. The site root `/` does not belong to any locale, handled by `src/worker/index.ts`, which returns a 302 redirect to `/en/` or `/zh-CN/` based on `Accept-Language` (`?lang=` overrides this).
- When modifying English documentation, you must also update the corresponding file under `i18n/zh-CN/docusaurus-plugin-content-docs/current/`. Updating only one language is **not allowed**.

## Fluent Design Conventions

- **Never hard-code Fluent color values.** All colors, border radii, durations, and easing curves come from `src/css/fluent-tokens.css`, which is generated by `npm run tokens:generate` from `webLightTheme` / `webDarkTheme` in `@fluentui/react-theme`.
- To add a token, add the official token name to the mapping table in `scripts/generate-fluent-tokens.mjs`, then regenerate the file. Do not write hexadecimal color values in `custom.css`.
- Always use official icons from `@fluentui/react-icons` (note: icon names do not include size suffixes, e.g., `RocketRegular`, not `RocketRegular16`).
- Component-level copy belongs in the `homeLabels` dictionary in `src/i18n/labels.ts`, separated by language. Do not hard-code Chinese in components.
- No extra marker is needed for GIF images; `custom.css` already applies Fluent card styling to `img[src$='.gif']`.

## Writing Conventions

- Beginner-facing documentation: explain "what it is" and "how to do it"; avoid jargon; give the conclusion first, then the details.
- Developer- and AI-agent-facing documentation: provide precise interfaces, fields, status codes, and copy-pasteable commands; avoid ambiguity.
- Use absolute paths for links in documentation (e.g., `/getting-started/overview`); Docusaurus automatically adds the locale prefix.
- Sidebar doc IDs must match directory names (using hyphens); otherwise the build fails with "These sidebar document ids do not exist".
- Use absolute paths for images (`/img/docs/xxx.jpg`); they are accessible in both languages.

## Build and Validation

```bash
npm ci --ignore-scripts     # Install dependencies
npm run tokens:generate     # Generate Fluent tokens
npm run typecheck           # TypeScript type check
npx docusaurus build        # Build (CI uses full minification)
```

Local environment limitations:

- If Terser minification fails due to sandbox permissions (`spawn EPERM`), use `npx docusaurus build --no-minify` instead.
- Do not add `@docusaurus/faster` or `@swc/core`: their native bindings cannot load on this machine.

CI uses `onBrokenLinks: 'throw'` and `markdown.hooks.onBrokenMarkdownLinks: 'throw'`; **any broken link will fail the build**—verify all links before committing.

## Local Configuration

The documentation site uses the same configuration model as the application repository:

- `.env.deploy.example` is the tracked template; `.env.deploy` is the only local configuration file and is Git-ignored.
- `scripts/deploy-env.mjs` is the single configuration entry point. It loads `.env.deploy` into the process environment and rejects legacy files (`.env`, `.env.local`, `.dev.vars`).
- `npm run config:env` creates `.env.deploy` from the template without overwriting an existing file.
- `npm start`, `npm run build`, `npm run serve` and `npm run deploy:cloudflare` load `.env.deploy` automatically. Values already present in the process environment win.
- CI never reads `.env.deploy`; it uses repository secrets and variables only.

## Versioned Documentation

Versioned documentation is not currently configured. To create a versioned release:

```bash
npm run docusaurus docs:version 1.0.0
```

After a version is created, content under `versioned_docs/` is an auto-generated snapshot; do not edit it manually.

## Commit Conventions

## Sensitive Information

- Never put API tokens, account IDs, or other credentials in the repository, logs, or documentation.
- Store repository secrets only in GitHub Actions secrets.
